# Shrimply Study (repo: StudyQuizWebApp)

React study app (flashcards, multiple choice, typing) hosted on GitHub Pages. The user's data is a `.shrimp` file they open and download.

## Workflow
- Build one step at a time, then stop. Don't start the next feature unasked.
- FEATURES.md is the ranked backlog. Update it at the end of every step.
- When the user asks for the "next step": suggest 1 to 3 `todo` items from FEATURES.md with a one-line reason each, then wait for their choice.

## Commands
- `npm run dev`, `npm run build`, `npm run preview`
- `npm test` (vitest), `npm run typecheck`
- Deploy: push to `main` and `.github/workflows/deploy.yml` publishes to https://mrflamesjr.github.io/shrimply-study/ (repo `MrFlamesJr/shrimply-study`, Pages source: GitHub Actions, already set).

## Architecture rules
- Storage only goes through `src/storage/`. Screens and state never touch files, zip, IndexedDB or localStorage directly (reading an image the user picks into a data URL, in `ImageSlot`, is input, not storage). A new backend is a new `StorageAdapter`, swapped in at the single `useLibrary(fileStorage)` line in `App.tsx`. The chosen theme is a browser preference (one localStorage key, `themePref.ts`), not part of the library.
- File format: one format only (version 1), no migrations or fallbacks while the app is unreleased. `library.json` has no ids and nests a quiz's grouped cards under `groups`; they are added in memory on open. Change `format.ts` in place.
- Every color, font, weight, text size, radius, line width, opacity, glow and spacing value is a token (see Themes). No hex/rgb values and no literal mix percentages outside the token files (component geometry like icon and control sizes, and media-query breakpoints, stay literal).
- Pure logic lives in `src/logic/` with a test file next to it.

## Minimal code
- Ask before adding any dependency.
- Smallest code that works. No abstraction until something is needed twice. Plain CSS; no UI kit, router or state library. Props, not context.
- Keep the file map below accurate when adding files.

## Visual style
- Dark, high contrast, calm, easy on the eyes during long study sessions. Calm's surfaces lean warm brown on a cool ground (asked for).
- Banned: gradients (except the toast stack's fade-out mask and the debug bar's striped mask, both asked for), shadows (except the study cards' soft drop shadow, `--glow-card`, deeper while the flashcard is hovered, asked for), glow, blur/glassmorphism (except the debug bar's striped glass, asked for; it is a test tool, not app UI, and the back-to-top button's glass, asked for), emoji, icon packs (hand-drawn inline SVG in `Icons.tsx` is fine), purple or neon accents, big rounded cards, decorative animation. These rules describe Calm, the default theme; see Themes for what the other themes may change.
- Motion: short functional transitions only (segmented slide, sidebar, card flip, flashcard hover glow, feedback bar, panels, group collapse, back to top), timing tokens `--dur-*`, off under `prefers-reduced-motion`. Keep them snappy: hover and UI changes 70 to 140ms, the sidebar slide 220ms, the card flip 300ms; slower feels unresponsive. Move things by transform, never by animating a width the page lays out around. The one ambient motion is the backdrop's moving layer (asked for, see Themes): very slight, still under reduced motion, every slide on one clock (`src/theme/drift.ts`).
- Calm selection: tinted fill plus thin accent border, not solid gold. One gold button per screen.
- Layout: hub-and-spoke (Home > Course > Quiz > Study): a course > quiz sidebar that closes to nothing (brand + toggle stay top left), breadcrumbs in a plain top row that stays put. Separate areas by tone and space, not divider lines. Each page has one primary action. Pages are capped by `--content-w`; study sessions are full screen (`--session-w` column), with a bottom feedback sheet after each answer (snaps up for more info) and a results screen at the end. Everything is reachable by keyboard; 44px touch targets below 800px.
- Inspired by how Quizlet and Kahoot structure studying, never their branding, colors or shapes.
- UI text: plain, short, sentence case. No em dashes.
- Dropdowns use the global `select` style (customizable select where supported).
- No box in a box: inside a filled box, text fields are underlined, pick-one bars get a thin outline (no fill) and fill only the chosen segment, selects are quiet until hovered. Cards in a group box are see-through boxes (the editor's style, on the quiz page too): inside a group box the `--surface*` tokens swap to see-through ones so the tint shows; popups use `--popup` (always solid).
- Buttons whose effect isn't obvious from the label (and icon-only buttons) get a native `title` tooltip.
- Icon-only buttons never fill on hover: the icon goes from `--text-muted` to `--text` (delete card: `--bad`; the group chevron and the back-to-top arrow stay `--text`, asked to be obvious) and springs up a size (the SVG's width and height, not a transform, so it stays sharp).
- Anywhere a card is shown, it can be edited: a pencil that opens `CardDialog`.
- Image previews (thumbnails) are always square, cropped to fill; only study shows an image whole. A side's text never shows without its image: wherever a term, definition or statement appears (cards, rows, choices, the sheet's answer), its image or its preview (`Thumb`) goes with it. Removing an image is a small ✕ badge hanging over its thumbnail's top-right corner (positioned, so it takes no layout room; quiet, never red), never a loose ✕. Deleting a card is a trash icon, so it never looks like that badge. Adding or removing an image never moves the field.

## Themes
- Files, the same for every theme: `src/theme/tokens.css` holds what all themes share (derived colors and theme-independent tokens). Each theme, Calm included, is one file `src/theme/theme-<id>.css` imported in `main.tsx` after `tokens.css`, plus an entry in `THEMES` (`model.ts`, the first is the default). Calm's block is `:root, :root[data-theme="calm"]`, so a missing or unknown `data-theme` gets it; every other is `:root[data-theme="<id>"]`. A theme file holds tokens only. Never style elements in it and never edit component CSS for one theme: a missing hook becomes a new token that is a no-op in Calm (like `--glow-*`).
- One template: every theme file is an about-comment (the look and each color's job), then one block with `color-scheme: dark` and exactly the tokens of `theme-calm.css`, in the same order, under the same section comments; only the values differ (`themes.test.ts` checks it). Sections: ground and text (`--bg`, `--text`, `--muted-l`, `--muted-c`), color jobs (`--accent`, `--selection-color`, `--ok`, `--bad`, `--danger`, `--warn`, `--info`, `--ink`), the shrimp (`--brand-shell`, `--brand-head`), blanks (`--blank-1` to `-4`), the eight `--group-*`, elevation (`--lift-*`), hover (`--hover-*`), tints (`--tint-*`, `--group-fill` / `-line` / `-chip`, scrim alphas), glow (`--glow-*`), backdrop (`--backdrop`, `--backdrop-drift`, `--backdrop-drift-w`, `--backdrop-drift-time`), type and shape (`--font-display`, `--display-*`, `--title-size`, `--text-brand`, `--text-score`, `--radius`). A value may use another template token (`var(--accent)`), never a token of the theme's own. Themes never override derived colors: a look the formulas can not give becomes a new knob, added to every theme file at once (Calm's value keeps Calm unchanged).
- Derive, don't repeat: surfaces and borders are relative oklch from `--bg`, lighter by a `--lift-*` step, gaining `--lift-chroma` color per step, in the hue `--lift-hue` (Calm: 0, a warm rose brown the user chose). Tints are `color-mix` with a `--tint-*` strength; hover is relative oklch from the accent. Never use a near-grey's own `h` in relative oklch: browsers drop it as powerless (it becomes 0), so the hue is a token.
- One job per color, so a screen never shows more than a couple of strong colors: the accent is the one action, the selection and the focus ring (a ring of another hue beside the accent clashes); green and red only mean right and wrong; `--danger` only means deleting for good; `--info` only info. Group colors are a touch softer than the accent so they never compete with it.
- Colors over colors agree in temperature and hue: main text is a near-neutral white; muted text takes the surfaces' hue (`--muted-l`, `--muted-c`, `--lift-hue`); a tinted zone (danger zone, group box, a right or wrong answer and its outline button) sets `--zone` and is listed in the zone rule at the top of `base.css`, which leans its muted text and borders toward that color by `--tint-muted`; bright text never sits straight on a colored surface (`--tint-rest` gives the outline buttons a faint fill of their own color).
- Contrast in every theme: text 4.5:1, large text (24px, or 18.66px bold) and icons 3:1, the accent button's text on the accent too. Check a theme in the browser, not only on paper: every screen, right and wrong answers, the sheet, dialogs, toasts, the danger zone, group boxes.
- What a theme other than Calm may change: glow only through the `--glow-*` tokens and only on the accent action, the progress bar, titles, focus and right/wrong answers (chosen options never glow), and the study cards (`--glow-card`, at rest in the theme's own light (Neon arcade's violet neon, Underwater's sea blue lit from above, Enchanted forest's moonlight), on hover via `--glow-card-hover` in the accent, as the flashcard is the action; asked for); a display font through `--font-display` for titles, the brand and the score only (body and card text stay Atkinson; fonts come from the Google Fonts link in `index.html`); corner radius. A backdrop behind the page ground through `--backdrop` and `--backdrop-drift` only (window-fixed layers behind `body`, the top row and the phone corner, clipped to each; cards, the sidebar and dialogs cover it), and only where asked for: Underwater's light beams and very faint caustics; Enchanted forest's faint moonlight shafts, fairy lights and low mist; Neon arcade's synthwave grid floor, pink horizon, stars and scanlines; Sassy unicorn's iridescent haze, a small pastel rainbow in the bottom-right corner and, at the very back, a large and very faint watercolor unicorn in the bottom-left corner of the open page ground (`src/theme/unicorn.webp`, the user's picture, its opacity baked in at 14%, placed with `--backdrop-position` / `-size` / `-repeat` from `--ground-x`, where the ground begins beside the open sidebar). An image in a backdrop stays faint enough that muted text crossing it keeps 4.5:1. Keep a backdrop very subtle and off the reading surfaces; it fades into the ground. Still banned in every theme: other gradients, other shadows, blur, emoji, other images or textures (an image is a file next to the theme, made small: WebP, sized for its display at about 2x), decorative animation (except the backdrop's moving layer `--backdrop-drift`, over the backdrop, asked for: Underwater's caustic net slides sideways one `--backdrop-drift-w` tile every `--backdrop-drift-time`; Enchanted forest's fairy lights slowly glow up and fade back with a small bob, Neon arcade's stars blink now and then, each on its own timing, animated inside their SVG, never the big lines; Sassy unicorn's few tiny pastel sparkles and hearts twinkle and slide sideways one tile every 140s, kept sparse and faint because they show through see-through controls; all very slight and still under reduced motion). Every theme is dark.
- The themes: Calm (default; dark, gold accent, warm brown surfaces on a cool ground); Neon arcade (near black, hot pink action and selection, violet structure, cyan info, sharp corners, glow, pixel font Silkscreen for titles, a synthwave grid floor to a pink horizon with stars and scanlines); Underwater (deep abyss blue, luminous aqua action, coral shrimp, kelp lime and anemone pink for right and wrong, light beams and faint caustics from the surface, faint bioluminescent glow, round Fredoka titles); Enchanted forest (dark pine with a hint of moss, under a spell, candle amber action, amethyst text selection, spring lime and crimson for right and wrong, gemstone group colors, faint moonlight shafts, fairy lights and an amethyst and teal mist, engraved Cinzel capitals glowing faintly like runes, small corners); Sassy unicorn (midnight plum, bubblegum pink action with a sparkly glow, lavender selection, mint and coral for right and wrong, a pastel rainbow of groups, a pink shrimp with a lavender head, sassy Lobster Two script titles, faint twinkling sparkles and hearts drifting over an iridescent haze).

## File map
- `src/model.ts`: data types (Library > Course > Quiz > Card; a card is a term card or a fill-in-the-blank `ClozeCard`, plus `Group` per quiz; `Card.group` is a group id; images `termImage`, `definitionImage`, a cloze card's `image` are data URLs), `IMAGE_TYPES` (extension > type), `SIDE_IMAGE` (side > its image field), study types (`FORMATS`, `StudyOptions`, `Question` with its prompt `side`), `GROUP_NAME_MAX`, `THEMES` (id > name, the first is the default) and `ThemeId`, `newId`, `emptyLibrary`
- `src/route.ts`: hash routes by name slug `#/`, `#/<course>`, `#/<course>/<quiz>`, `#/<course>/<quiz>/edit`, `#/<course>/<quiz>/study/<format>`, `#/_debug` (not linked); `href`, `resolve` (the course and quiz an address names, as far as they exist, and which one is `missing`; App then goes to the nearest page with a note), `usePlace` (`resolve` that follows renames: the page stays found by id and the address moves to the new name 300ms after the typing pauses, as browsers limit address changes), `go`, `goToNew` + `takeCreated` (select a just-created name once), `redirect`, `useRoute`
- `src/state/useLibrary.ts`: `LibraryApi`, the only data API the UI uses (`ready` once the backup is read, App renders nothing before; edits incl. `setCards` and `updateCard`, `hasChanges`, backup sync 300ms after the last edit, close warning, open (from the file picker, or any loader passed in) / download)
- `src/storage/StorageAdapter.ts`: `{ loadLabel, saveLabel, loadHint, saveHint, load(), save(library) }`
- `src/storage/format.ts`: `.shrimp` = zip with `library.json` and `images/` (an image field names a file there, `"termImage": "1.png"`; written numbered in write order, one file per distinct image, stored uncompressed; unnamed files ignored; a cloze card is `{ "type": "cloze", "statement", "explanation"? }`: `{ }` marks blanks, `\{ \} \\` are literal, explanation is text for one blank or a list with one entry per blank; in memory always a list, null for none and "" for one opened in the editor but still empty); `libraryToJson(library, images?)` (no ids, one card per line, groups nested with an optional `color` and written only when there are some; fills `images` with data URL > file name), `libraryFromJson(text, files?)`, `checkLibrary(data, 'new' | 'stored', files?)` (strict, errors name the spot; a file can not have an empty or spaces-only name, nor two courses, or two quizzes in one course, with the same `slug`; stored images are data URLs), `encodeLibrary`, `decodeLibrary`

- `src/storage/themePref.ts`: `loadTheme` / `saveTheme`, the chosen theme in localStorage (blocked or unknown falls back to the default)
- `src/storage/browserBackup.ts`: IndexedDB copy (one JSON text) of the in-memory library (with ids and images) and changed ids; async; `clearBackup`, `breakBackup`, `backupSize` for the debug page

- `src/theme/tokens.css`: tokens shared by every theme, in two blocks (derived colors, theme-independent; see Themes): `--lift-*` elevation, `--tint-*` strengths, `--glow-*` effects, `--font-display` / `--title-size` titles, `--weight*`, `--line*`, `--dim*`, `--focus` ring color, `--danger` / `--danger-soft` (the danger zone), `--brand-*` logo colors, `--group-*` group colors, `--corner-w` closed corner, `--content-w` page column, `--session-w` study column, `--card-img-h` study image, `--thumb-h` / `--thumb-list-h` thumbnails, `--text-*` repeated text sizes, `--tap` touch target; styles that use the tokens, one file per area, imported from `main.tsx` in cascade order: `base` (zone rule, reset, type, buttons, inputs, Segmented), `shell` (corner, top row, sidebar, page), `pages` (title, empty state, tiles, quiz options, card rows, danger zone), `dialogs`, `editor` (cards, image slots, selects, groups, palette), `study`, `sheet`, `results`, `motion` (incl. reduced motion), `toasts`, `cloze`, `debug` (debug page and bar). A new rule goes in its area's file; keep the import order
