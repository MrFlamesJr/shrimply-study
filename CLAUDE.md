# Shrimply Study (repo: StudyQuizWebApp)

React study app (flashcards, multiple choice, typing) hosted on GitHub Pages. The user's data is a `.shrimp` file they open and download.

## Workflow
- Build one step at a time, then stop. Don't start the next feature unasked.
- FEATURES.md is the ranked backlog. Update it at the end of every step.
- When the user asks for the "next step": suggest 1 to 3 `todo` items from FEATURES.md with a one-line reason each, then wait for their choice.

## Commands
- `npm run dev`, `npm run build`, `npm run preview`
- `npm test` (vitest), `npm run typecheck`
- Deploy: push to `main` and `.github/workflows/deploy.yml` publishes to https://mrflamesjr.github.io/shrimply-study/ (repo `MrFlamesJr/shrimply-study`, Pages source: GitHub Actions, already set). A release that raises `FORMAT_VERSION` first adds that version's fixtures to `src/storage/fixtures/` (a file's `library.json` with every field, and a backup). A release with something new for users adds its notes at the top of `RELEASES` (`src/releaseNotes.ts`), dated the day it goes out, which shows everyone the welcome page once more with them.

## Architecture rules
- Storage only goes through `src/storage/`. Screens and state never touch files, zip, IndexedDB or localStorage directly (reading an image the user picks into a data URL, in `ImageSlot`, is input, not storage). A new backend is a new `StorageAdapter`, swapped in at the single `useLibrary(fileStorage)` line in `App.tsx`. Google Drive sits beside the file adapter, not instead of it: `googleDrive.ts` is the only file that talks to Google, `useLibrary` reaches it (`lib.drive`), and the browser backup keeps which Drive file the library came from (`drive`). Browser preferences are one localStorage key each, named `shrimply-...` (so `resetPrefs` finds them), not part of the library: the chosen theme (`themePref.ts`), the quiz page's minimized tips (`tipsPref.ts`), the study options (`studyPref.ts`) and the last release whose welcome page was shown (`welcomePref.ts`).
- File format: versioned; every older version keeps opening (asked for). `FORMAT_VERSION` (`model.ts`) is the current one; `format.ts` reads and writes only it, no fallbacks. Any change to what a file or the browser backup holds (a field or card type added, renamed, removed or read differently) goes in the next version: changes not yet on `main` share one version; the first one after a release raises `FORMAT_VERSION` and adds a step in `src/storage/upgrade.ts` that turns the previous version's data (file and backup form) into it (as is when something was only added). Old versions are handled there and nowhere else. A released version's step and its fixtures (`src/storage/fixtures/v<N>.json`, `v<N>-backup.json`) are never edited; `upgrade.test.ts` opens them all. A library from a newer version asks to reload. `library.json` has no ids and nests a quiz's grouped cards under `groups`; they are added in memory on open. Change `format.ts` in place.
- Every color, font, weight, text size, radius, line width, opacity, glow and spacing value is a token (see Themes). No hex/rgb values and no literal mix percentages outside the token files (component geometry like icon and control sizes, and media-query breakpoints, stay literal; a theme's images, its `.svg` files and `unicorn.webp`, bake in their colors, as tokens can not reach an image).
- Pure logic lives in `src/logic/` with a test file next to it.

## Minimal code
- Ask before adding any dependency. `@dnd-kit` (asked for) drags a sequence's steps, only in `StepList`.
- Smallest code that works. No abstraction until something is needed twice. Plain CSS; no UI kit, router or state library. Props, not context.
- Keep the file map below accurate when adding files.

## Visual style
- Dark, high contrast, calm, easy on the eyes during long study sessions. Calm's surfaces lean warm brown on a cool ground (asked for).
- Banned: gradients (except the toast stack's fade-out mask, the debug bar's striped mask, the top row glass's fade-out mask, all asked for), shadows (except the study cards' soft drop shadow, `--glow-card`, deeper while the flashcard is hovered, and a hovered add pill's inner glow: the outline's accent fading in from every edge and gone within a few px (an inset shadow, `--pill-fade`, strength `--tint-pill` per theme; the middle stays clear, so the glass shows under the label), both asked for), glow, blur/glassmorphism (except the debug bar's striped glass, asked for; it is a test tool, not app UI, and the back-to-top button's glass and the top row's frosted glass (what scrolls under it fogs away, fading out just below its edge; the phone corner too), and the new-quiz tile's glass (faint at rest, never fully clear; denser and more blurred on hover), and the editor's "Add new card" box, which takes the same faint glass on the page ground (clear inside a group box), and the danger zone, which shares that glass with a red tint mixed in (the same tokens, so one edit changes both), asked for), emoji, icon packs (hand-drawn SVG files in `src/icons/`, drawn inline by `Icons.tsx`, are fine), purple or neon accents, big rounded cards, decorative animation. These rules describe Calm, the default theme; see Themes for what the other themes may change.
- Motion: short functional transitions only (segmented slide, sidebar, card flip, flashcard hover glow, feedback bar, panels, group collapse, the question column gliding aside as the feedback panel comes in (`--dur-slide`), steps making way while one is dragged (`--dur`), an info box minimizing to its title, the minimized info box growing slightly while hovered, back to top, a checked sequence's line drawing itself from its step to its correct place, then its head (`--dur-draw`, asked for), an image drop target's slowly pulsing dashed outline (asked for), an explanation's eraser fading in, a field's floating label rising above it, then its bracket drawing out of it like a pen stroke (and back into it before it falls; strokes of `--float-step`) (asked for), the add-card pills' hover, kept calm: an accent copy of the edge growing from just inside it out onto it as it fades, with the border and fill easing in (`--dur-echo`, `--dur-echo-fill`, slower on purpose, asked for)), timing tokens `--dur-*`, off under `prefers-reduced-motion`. Keep them snappy: hover and UI changes 70 to 140ms, the sidebar slide 220ms, the card flip 300ms; slower feels unresponsive. Move things by transform, never by animating a width the page lays out around. The one ambient motion is the backdrop's moving layer (asked for, see Themes): very slight, still under reduced motion. The Start button's looping hover pulse is also asked for (`--dur-start-ping`, `--dur-start-push`), and so is edit mode's outline: one thick, faint accent line of long and short dashes around the whole editor, `--space-6` out from the content at the sides and bottom (the content keeps its place and width) and starting lower at the top so it stays clear of the top row's fog (`EditOutline`, an SVG path so its dashes can move and text can follow it) where every few dashes, always between two long ones with a wider gap on each side, one is the word "Editing" (small, spaced pixel capitals, the same in every theme (Silkscreen bold, `--font-dash`, `--text-dash`, `--dash-tracking`), not much taller than the line (`--line-edit`) and never thickened, following the line round the corners; part of the pattern, exactly as faint as the dashes (`--dim-faint`), not text to read, so the 4.5:1 rule does not apply to it, asked for), whose dashes and words nudge a few px round together, settling quickly (`--dur-edit-move`), and whose line slowly thickens a touch (`--line-edit-hover`, `--dur-edit-swell`) when the pointer crosses the line into the editor, and back when it leaves; very subtle, so it never distracts (asked for), still under reduced motion. Its easter egg, also asked for: a click on the line itself spins the dashes and words a short way round (two repeats of the pattern) with a wind-up back first that holds for a beat as if about to snap, a snappy start, a slow-motion finish and a small bounce (`spinCurve`, `--dur-edit-spin`); no pointer cursor, not under reduced motion.
- Calm selection: tinted fill plus thin accent border, not solid gold. One gold button per screen.
- Layout: hub-and-spoke (Home > Course > Quiz > Study): a course > quiz sidebar that closes to nothing (brand + toggle stay top left), breadcrumbs in a plain top row that stays put. Separate areas by tone and space, not divider lines (except a faint see-through line between a fill-in-the-blank card's blanks, in the editor and the card rows, asked for). Each page has one primary action. Pages are capped by `--content-w`; study sessions are full screen (`--session-w` column), with a feedback sheet after each answer (from the right as a full-height panel at 1000px and up, asked for; a bottom sheet below that) and a results screen at the end. Right and wrong show in the question itself (asked for): the picked or typed answer and the right one are marked ✓ or ✗, a blank's statement fills it in, and a checked sequence shows the order it was put in beside the correct order, both lists as tall as the taller one (the shorter spreads its steps evenly, never stretching them), and pointing at a step at either end shows the one line from it to its correct place, its arrowhead turned the way the line arrives (asked for). The sheet never repeats the answer: it holds Correct! or Incorrect! (big: the theme's display font at `--text-result`) in its color under a bar of that color (asked for; flashcards: "Did you know it?"), which card, blank or step a wrong answer belongs to, for a pick-all question how many were wrong and how many missed, or for a sequence put in order how many steps were in the wrong place (asked for), the card's explanation as a banner whose left edge takes the theme's explanation color and shape (asked for) (its text scrolls on its own, with a slim scrollbar) and the actions, big buttons that never scroll, beside them at the column's bottom right (asked for). Everything is reachable by keyboard; 44px touch targets below 800px.
- Inspired by how Quizlet and Kahoot structure studying, never their branding, colors or shapes. The one exception is the Quizlet and Kahoot themes, which copy those apps' colors, fonts and styles on purpose (asked for), but never their logos or backgrounds.
- UI text: plain, short, sentence case. No em dashes. Correct, never right, for what is correct (asked for).
- Dropdowns use the global `select` style (customizable select where supported).
- A text field's name is its floating label (`label` on `AutoText`, asked for): in the empty box like a placeholder, above it once it has focus or text, its text lined up with the field's. Floated, a thin bracket ties it to its field (asked for): from the name to the field's top left corner (the theme's `--radius`, capped), down the left edge to halfway, then one dash, never touching the underline (no long lines across the field: clutter); it takes the underline's color (border, `--border-strong` while pointed at, accent while focused), and so does the name while focused, but never red: a field's error (missing or refused text) shows on its underline and its message, never on the bracket (asked for). Labelled fields are underlined, never boxed. Every text field shows its state the same way (asked for): its line (underline, or a boxed field's border) brightens to `--border-strong` while the field is pointed at (its floating label and its eraser count as the field), takes the accent while focused and red when missing; only the resting line differs (fainter in answer and step lists, hidden on page titles and group names). One set of state rules in `base.css`; never restate them per field. Never a placeholder and a caption that say the same thing; a list's entries (answers, steps) have no label or placeholder, as the list's heading (or the step number) names them. A placeholder alone only where a label has no room (an inline name next to chips, the study answer box).
- Enter is the same in every text box: it goes on to the next box, and Shift+Enter starts a new line. The boxes of a card (editor) or a dialog are a group: from the last box Enter goes to the next card (a new one at the end) or presses the dialog's main button. One-line boxes (names, the typed answer) never take a line break: Enter (Shift+Enter too) confirms. In a list (answers, steps), Enter in the last box adds one, and in an empty last box leaves the list (that box goes). The one exception is the import paste box, where each line is a card.
- No box in a box: inside a filled box, text fields are underlined, pick-one bars get a thin outline (no fill) and fill only the chosen segment, selects are quiet until hovered. Cards in a group box are see-through boxes (the editor's style, on the quiz page too): inside a group box the `--surface*` tokens swap to see-through ones so the tint shows; popups use `--popup` (always solid).
- Buttons whose effect isn't obvious from the label (and icon-only buttons) get a native `title` tooltip.
- Icon-only buttons never fill on hover: the icon goes from `--text-muted` to `--text` (delete card: `--bad`; the group chevron and the back-to-top arrow stay `--text`, asked to be obvious) and springs up a size (the SVG's width and height, not a transform, so it stays sharp). On the way up it pops to catch the eye (`icon-pop`: a brief scale past the new size and back, `--dur-pop`), always inside a fixed cell (the button, or the info box's chevron cell) so nothing around it moves. That icon pop is one shared rule in `base.css` (icon buttons, the sidebar toggle, the info box's chevron), and so is the fold chevron's turn (`rotate`, up while open: group boxes, the info box); reuse them, never copy them.
- Anywhere a card is shown, it can be edited: a pencil that opens `CardDialog`, which is the editor's own `EditCard` in a modal (the same fields, never a copy).
- Image previews (thumbnails) are always square, cropped to fill; only study shows an image whole. A side's text never shows without its image: wherever a term, definition or statement appears (cards, rows, choices, a checked typed answer), its image or its preview (`Thumb`) goes with it. Removing an image is a small ✕ badge hanging over its thumbnail's top-right corner (positioned, so it takes no layout room; quiet, never red), never a loose ✕. Deleting a card is a trash icon, so it never looks like that badge. Removing a field that can go (an explanation, a choice question's answer, a step) is an eraser (`EraserIcon`), never a ✕ (asked for), inside the box at its end (`AutoText`'s `erase`), shown only while that one field is hovered or focused (its room always kept, asked for); a blank is not a field, so removing one stays a ✕ at the end of its row (asked for). Adding or removing an image never moves the field.

## Themes
- Every style edit is for all seven themes, not just the one on screen: think through how it reads with each theme's colors, display font, corners, glow and backdrop. It is not done until the theme check (the last item of this section) passes.
- Files, the same for every theme: `src/theme/tokens.css` holds what all themes share (derived colors and theme-independent tokens). Each theme, Calm included, is one file `src/theme/theme-<id>.css` imported in `main.tsx` after `tokens.css`, plus an entry in `THEMES` (`model.ts`, the first is the default). Calm's block is `:root, :root[data-theme="calm"]`, so a missing or unknown `data-theme` gets it; every other is `:root[data-theme="<id>"]`. A theme file holds tokens only. Never style elements in it and never edit component CSS for one theme: a missing hook becomes a new token that is a no-op in Calm (like `--glow-*`).
- One template: every theme file is an about-comment (the look and each color's job), then one block with `color-scheme: dark` and exactly the tokens of `theme-calm.css`, in the same order, under the same section comments; only the values differ (`themes.test.ts` checks it). Sections: ground and text (`--bg`, `--text`, `--muted-l`, `--muted-c`), color jobs (`--ok-fill`, `--bad-fill` and `--role-ink`: the right and wrong buttons filled solid where `--role-solid` is 1, as in Kahoot; `--accent`, `--accent-fill` and `--accent-ink` (the filled accent buttons and their text: the accent itself, or a deeper step of its hue where the accent is too light to carry text, as in Quizlet), `--selection-color`, `--ok`, `--bad`, `--danger`, `--warn`, `--info`, `--explain`, `--ink`), the shrimp (`--brand-shell`, `--brand-head`), blanks (`--blank-1` to `-4`), the eight `--group-*`, elevation (`--lift-*`; `--lift-sidebar` is the sidebar's own step, the first surface's unless set apart), the filled accent buttons (`--hover-*`, and `--accent-hint`: how much of their text a key hint on them keeps), tints (`--tint-*`, `--tint-keep` among them: how much of the ground's own color stays under a role's tint, `--role-chroma` and `--role-turn`: how colorful a right or wrong fill is and how far its hue turns away from yellow, `--role-solid`: right and wrong buttons filled solid, `--group-fill` / `-line` / `-chip`, scrim alphas), glow (`--glow-*`), backdrop (`--backdrop`, `--backdrop-drift`, `--backdrop-drift-w`, `--backdrop-drift-time`), type and shape (`--font-display`, `--display-*`, `--title-size`, `--text-brand`, `--text-score`, `--text-info-title`, `--text-result`, `--radius`, `--radius-pill` (the add-card pills: round, or the theme's `--radius` where corners are sharp)), the explanation banner's edge (`--explain-edge`, `-w`, `-h`, and `-fill`: the same tile's line and everything right of it, where the banner's fill shows, so none of it shows left of a shaped line, asked for). A value may use another template token (`var(--accent)`), never a token of the theme's own. Themes never override derived colors: a look the formulas can not give becomes a new knob, added to every theme file at once (Calm's value keeps Calm unchanged).
- Derive, don't repeat: surfaces and borders are relative oklch from `--bg`, lighter by a `--lift-*` step, gaining `--lift-chroma` color per step, in the hue `--lift-hue` (Calm: 0, a warm rose brown the user chose). Tints are `color-mix` with a `--tint-*` strength; hover is relative oklch from the accent. Never use a near-grey's own `h` in relative oklch: browsers drop it as powerless (it becomes 0), so the hue is a token.
- One job per color, so a screen never shows more than a couple of strong colors: the accent is the one action, the selection and the focus ring (a ring of another hue beside the accent clashes); green and red only mean right and wrong; `--warn` (yellow or orange in every theme) only a warning, or a correct option left unpicked in a pick-all question (Missed, asked for); `--danger` only means deleting for good; `--info` only info; `--explain` only a card's explanation (the feedback sheet's banner). Group colors are a touch softer than the accent so they never compete with it.
- Colors over colors agree in temperature and hue: main text is a near-neutral white; muted text takes the surfaces' hue (`--muted-l`, `--muted-c`, `--lift-hue`); a tinted zone (danger zone, group box, a right or wrong answer and its outline button) sets `--zone` and is listed in the zone rule at the top of `base.css`, which leans its muted text and borders toward that color by `--tint-muted`; bright text never sits straight on a colored surface (`--tint-rest` gives the outline buttons a faint fill of their own color). A role's tint (right, wrong, danger, info, a group box) is a container in the role's own hue, never a see-through tint over a ground of another hue, where complementary hues cancel into grey and others turn (asked for): danger, info and group boxes are mixed in OKLCH into the ground with only `--tint-keep` of its own color left (`--role-ground`; the danger zone's glass sits on `--role-veil`). Right and wrong fills (their buttons, a marked answer) are deep, clear tones of their own hue: the surface's or ground's lightness at a set chroma (`--role-chroma`), since a dark red or green with too little chroma reads brown or olive, with the hue turned away from yellow by `--role-turn` (wrong toward crimson, right toward true green: a dark coral turns rust and a dark lime olive), while their text keeps the role's color; a key hint inside such a button takes its text color (asked for). A see-through accent tint (a chosen segment, a picked choice) first takes the color out of what is under it (`backdrop-filter: saturate(var(--tint-keep))`, a color filter, no blur). Where a theme's ground and lines are strongly colored (Quizlet, Kahoot), `--tint-keep` is low and `--tint-muted` high, so a zone's lines and key hints take its color too. Judge a tint by its real composite (its OKLCH hue against the role's, in every theme and over every ground it sits on), never as a lone swatch.
- Color theory, applied for real and reasoned in OKLCH (perceptual, so equal steps look equal; never in hex or HSL, whose lightness is wrong): lightness (L) does hierarchy and contrast, hue (h) does meaning, chroma (C) does emphasis.
  - Value first: a screen must read in greyscale (ground, surfaces, text and the one action told apart by L alone) before hue helps.
  - Harmony: each theme is built on a named scheme of its ground and accent hues (Calm is complementary: gold accent at h 83 opposite the cool ground at h 258, warm rose-brown surfaces between). A new hue is placed by its angle to those: analogous (within about 30°), complementary (about 180°), split-complementary (about ±150°) or triadic (about 120°). When a theme's colors are chosen or changed, its about-comment names the scheme.
  - Proportion: about 60% ground and surfaces, 30% structure (muted text, lines, tints), 10% or less strong color; the accent is the smallest, brightest area.
  - Chroma by area: the bigger the area, the lower its chroma (surfaces near grey, tints faint); high chroma only on small marks. On a dark ground, saturated color glares and looks brighter than its L (Helmholtz-Kohlrausch), so lower C before L.
  - Temperature: warm and bright come forward (the action), cool and dark recede (ground, structure).
  - Peers (the `--group-*` colors, the blanks) share one L and C and are spread around the hue wheel, so each weighs the same and neighbors never look alike.
  - No vibrating pairs: two high-chroma colors at about the same L (complements, red beside blue) never touch; part them by L or drop one's C.
  - Simultaneous contrast: a color shifts with what surrounds it, so judge it on every surface it sits on, never as a lone swatch.
  - Color blindness: about 1 in 12 men can not tell red from green by hue, so color is never the only sign of meaning (right and wrong also show a mark or a word).
- Choosing a color: take the token whose job it is; never invent a color for one spot. When no token fits, the new token gets a value in every theme file at once, placed by that theme's scheme (above), not Calm's value copied. Two saturated colors never sit straight against each other (a solid badge on another color's fill, one color's text on another's): one steps back to a tint or a muted line.
- Contrast in every theme, measured (DevTools' contrast readout, or the computed colors), never judged by eye, against what is really behind the element: its surface after any tint, a see-through group box over its fill, glass over the brightest part of the backdrop, its own hover or chosen fill. Text 4.5:1, muted and placeholder text included; large text (24px, or 18.66px bold), icons and the focus ring 3:1; the accent button's text on the accent too.
- What a theme other than Calm may change: glow only through the `--glow-*` tokens and only on the accent action, the progress bar, titles (an info box's title too, in the info color, `--glow-info`), focus and right/wrong answers (chosen options never glow; Kahoot's "glow" is hard-edged only, after its flat lighting: a darker edge inside the bottom of its buttons and right and wrong answers, and a small hard shadow under titles, asked for), and the study cards (`--glow-card`, at rest in the theme's own light (Neon arcade's violet neon, Underwater's sea blue lit from above, Enchanted forest's moonlight, Quizlet's faint grey-blue night shadow, Kahoot's hard dark bottom edge), on hover via `--glow-card-hover` in the accent, as the flashcard is the action; asked for); a display font through `--font-display` for titles (an info box's title too), the brand, the score and the feedback sheet's Correct! only, each sized to how big that font draws (`--title-size`, `--text-brand`, `--text-score`, `--text-info-title`, `--text-result`) (body and card text stay Atkinson; fonts come from the Google Fonts link in `index.html`); corner radius; the explanation banner's edge shape (`--explain-edge`, an SVG mask tile (`src/theme/<theme>-edge.svg`) repeated down it, asked for: Calm a straight line, Neon arcade a sharp zigzag, Underwater a wave, Enchanted forest a chain of gems, Sassy unicorn cloud scallops, Quizlet a thicker straight line, Kahoot a ribbon folded down the edge, its facets in two flat tones, one geometric line, never a row of shapes) and color (`--explain`, placed by the theme's scheme: Calm's info blue, Neon arcade's cyan, Underwater's seafoam, Enchanted forest's amethyst, Sassy unicorn's lavender, Quizlet's soft dusty sky blue (the yellow was too intense), Kahoot's pale lavender (not teal, asked for); its fill is the theme's raised surface touched with that color by `--tint-explain`). A backdrop behind the page ground through `--backdrop` and `--backdrop-drift` only (window-fixed layers behind `body`; the top row's glass fogs it; cards, the sidebar and dialogs cover it), and only where asked for: Underwater's light beams and very faint caustics; Enchanted forest's faint moonlight shafts, fairy lights and low mist; Neon arcade's synthwave grid floor, pink horizon and stars; Kahoot's own loose scatter of faint geometric shapes (triangles, diamonds, circles and squares, some outlined, some flat, tiled every 560px; a nod to its answer shapes, never a copy of a Kahoot background, asked for); Sassy unicorn's iridescent haze, a pastel rainbow in the bottom-right corner, as big as the unicorn so the two balance (one shared size, at most 560px and 45% of the open ground so they never meet), and, at the very back, a large and very faint watercolor unicorn in the bottom-left corner of the open page ground (`src/theme/unicorn.webp`, the user's picture, its opacity baked in at 14%, placed with `--backdrop-position` / `-size` / `-repeat` from `--ground-x`, where the ground begins beside the open sidebar). An image in a backdrop stays faint enough that muted text crossing it keeps 4.5:1. Keep a backdrop very subtle and off the reading surfaces; it fades into the ground. Still banned in every theme: other gradients, other shadows, blur, emoji, other images or textures (an image is a file next to the theme, made small: an SVG (`<theme>-drift.svg`, `-edge.svg`, `-edge-fill.svg`) or a WebP sized for its display at about 2x), decorative animation (except the backdrop's moving layer `--backdrop-drift`, over the backdrop, asked for: Underwater's caustic net slides sideways one `--backdrop-drift-w` tile every `--backdrop-drift-time`; Enchanted forest's fairy lights slowly glow up and fade back with a small bob, Neon arcade's stars blink now and then, each on its own timing, animated inside their SVG, never the big lines; Sassy unicorn's few tiny pastel sparkles and hearts twinkle and slide sideways one tile every 140s, kept sparse and faint because they show through see-through controls; Kahoot's geometric shapes each spin very slowly in place, about a turn every two minutes, some the other way, while its circles, the same at every angle, breathe a little instead (asked for); all very slight and still under reduced motion).
